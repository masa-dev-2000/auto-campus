## STEP 1: ヒアリング

`docs/project/hearing.md` が存在する場合は読み込んで未回答の項目があれば続きから始める。

**1問ずつ順番に聞く。回答を受け取ってから次の問いに進む。**

```
Q1. 完成した日のプレスリリース見出しを1文で教えてください。
    （例: 「議事録が自動で作れる、エンジニアチーム向けツール」）
```
→ 回答後:
```
Q2. 何を作りたいですか？（1〜2文で）
```
→ 回答後:
```
Q3. なぜ作ろうと思いましたか？（きっかけ・解決したい問題）
```
→ 回答後:
```
Q4. 誰のためですか？その人は今この問題をどうやって解決していますか？
```
→ 回答後:
```
Q5. なぜ今のやり方では不十分ですか？（具体的な不満）
```
→ 回答後:
```
Q6. Appetite: この機能に使える最大時間は？
    （例: 2週間。超えたら機能を削る、延長はしない）
```
→ 回答後:
```
Q7. 絶対に必要な機能は？（3つまで）
```
→ 回答後:
```
Q8. 技術的な制約・条件は？（言語・フレームワーク等。なければ「特になし」）
```

全問回答後、1文で確認する:
「つまり、〇〇が〇〇するために〇〇を作る、ということですね。」
